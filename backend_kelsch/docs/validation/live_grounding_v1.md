# V-01 live grounding pipeline probe, version 1

Date: 2026-10-10. [Machine summary](live_grounding_v1.json) and [compressed turn/challenge ledger](live_grounding_v1_traces.json.gz) are generated by `backend_kelsch.scripts.eval_live_grounding`. Inputs are the three versioned cases, Notebook 04's authored novice/competent/expert utterances, and its existing adversarial candidates. This run uses the *typical* illustrative threshold vector (3 cases × 3 authored scripts). Script intents are stored as fixture metadata; the pipeline's predicted intents are recorded separately. No learner performance or faculty expected answer is inferred.

Run from repository root:

```bash
LLM_ENABLED=false PYTHONPATH=backend python -m backend_kelsch.scripts.eval_live_grounding
PYTHONPATH=backend python -m backend_kelsch.scripts.eval_live_grounding --live --pricing /private/prices.json --report /private/live_report.json --traces /private/live_trace.json.gz
```

`--live` requires `LLM_ENABLED=true`, SDK-detected credentials, and explicit private report/trace paths. Without credentials, it performs only the offline evaluation, sets `live_status: NOT EVALUABLE`, and makes no model calls. Credentials stay in the operator's environment/profile, never in a report; model replies should also stay outside Git. Live inference has not been run for this committed report: the credential preflight found none. The example private price file must give `currency: "USD"`, the exact configured AWS `region`, `effective_date`, an HTTPS `source_url`, and `models` mapping exact configured model IDs to nonnegative `input_usd_per_million` and `output_usd_per_million`. Check the rates against [AWS Bedrock pricing](https://aws.amazon.com/bedrock/pricing/) at run time. Missing rates, missing response usage, or cache tokens make the *total* cost null; an unpriced partial sum is never presented as a total. Bedrock's Converse response includes input, output and total usage counters ([AWS API reference](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_TokenUsage.html)).

Each turn records case file SHA-256/version, utterance, fixture intent, classifier output, allowed/disclosed/cited fact IDs and sources, trust events, delivered text, verifier attempts and blocked reasons, fallback, step/total latency, and model calls with model ID, prompt name/version, token usage and estimated per-call cost when known. The summary retains prompt file hashes and versions; the verifier prompt is version 5. Candidate replies are **not delivered** during the challenge check. Their deterministic decision, optional judge decision, call usage, latency, and pending faculty status appear in the ledger.

The added candidates probe negation, an invented patient value echoed from a student's words, a case age reused as a blood-sugar value with the wrong unit, and an unsupported cancer conclusion. These are adversarial *hypotheses* with `faculty_expected_supported: null`. The numeric checker accepts the echoed value because it sees the student's number; the independent semantic check must decide whether the patient asserts that value as their own. The wrong-unit examples also pass the numeric check because the case age supplies the numeral. The version 5 verifier prompt explicitly distinguishes attribution to the student from a new first-person patient claim. This is a prompt change, not a clinical accuracy result.

The shared verifier previously interpreted a JSON object without `unsupported` as an empty list and accepted the reply. It now rejects missing/malformed lists and malformed flagged items. The pipeline logs failed phrase/judge calls with any Bedrock usage already returned, and measures template fallback time. Unknown usage stays null rather than an invented zero.
